# TrajPlayer v0.1.0-alpha.8

This prerelease focuses on million-atom CPU latency, exact frame ownership,
workload-aware memory decisions, and reproducible real-trajectory benchmarks.
It preserves the alpha.7 UI, molecular appearance, and sequential no-skip
playback behavior.

## Rendering And Playback

- Million-atom depth ordering now uses a native `O(N + 256)` counting pass
  instead of running `stable argsort` after assigning the same 256 depth bins.
- The native order is exactly equivalent to the previous far-to-near bucket
  order, so sphere, bond, occlusion, and antialiasing output are unchanged.
- A submitted `RenderTicket` must be consumed by `paintGL` before
  `frameSwapped` can acknowledge it. Resize, expose, and camera redraws cannot
  accidentally confirm an unrelated pending trajectory frame.
- The reference RTX 4070 Laptop 100,000-atom and 99,999-bond scene retained
  about 60 FPS with zero dropped frames, duplicate presentations, or complete
  renderer-side CPU frame copies.

In a local Linux/WSL native hot-path benchmark, one million depth values took a
4.79 ms median versus 12.63 ms for the previous stable-sort path, a 2.64x
improvement. Hardware and compiler results will vary.

## Streaming And Memory

- The adaptive frame cache now receives the user's selected playback rate
  rather than a fixed 60 FPS assumption.
- Decode latency is evaluated against the active frame deadline, and benchmark
  reports expose both the selected rate and computed deadline.
- A conservative process-RSS soft limit can trigger immediate cache shrink;
  available-memory and cgroup pressure checks remain in place.
- Playback remains strictly sequential. Missing a timing deadline lowers
  cadence and never skips a trajectory frame.

## Real-Trajectory Validation

- `scripts/bench_scenarios.py` measures metadata and first-frame opening,
  random/sequential/seek-storm reads, and bounded no-skip streaming soaks using
  local ASE, XYZ/extXYZ, or Gromacs files.
- Scenario JSON records reader latency, decode throughput, RSS, cache state,
  lease balance, source sizes, and hardware context without altering the
  trajectory or deleting its index.
- `scripts/compare_perf.py` now compares matching real-file scenarios and
  warns when platform or processor context differs.
- Release smoke tests require the packaged native extension to expose the new
  depth-order entry on Windows, Linux, Apple Silicon, and Intel macOS.

## Windows

Download `TrajPlayer-Windows-x64-v0.1.0-alpha.8.zip` from the assets below, not
the source archive under **Code > Download ZIP**. Extract the complete archive
and run `TrajPlayer\TrajPlayer.exe`. Python and Conda are not required. Keep
`_internal` beside the executable and do not share the EXE by itself.

## Linux

Download and completely extract
`TrajPlayer-Linux-x86_64-v0.1.0-alpha.8.tar.gz`, then run:

```bash
chmod +x TrajPlayer/TrajPlayer
./TrajPlayer/TrajPlayer
```

Python is not required. Linux x86_64, OpenGL 3.3, and common Qt XCB runtime
libraries are required.

## macOS

Download `TrajPlayer-macOS-arm64-v0.1.0-alpha.8.zip` for Apple Silicon or
`TrajPlayer-macOS-x86_64-v0.1.0-alpha.8.zip` for Intel. Extract the archive and
open `TrajPlayer-macOS/TrajPlayer.app`. Python is not required.

The app is ad-hoc signed but not Apple-notarized. On first launch, Control-click
the app, choose **Open**, and confirm. macOS 13 or newer and OpenGL 3.3 are
required.

Use **Open** or drag files into TrajPlayer. GRO and XTC/TRR can be selected or
dropped together; a same-named GRO beside XTC/TRR is detected automatically.
This remains an alpha release, so keep original trajectories and report
reproducible issues through GitHub Issues.
